# Homepage Builder Skill (프리미엄 홈페이지 제작 & 배포 종합 가이드)

사용자 맞춤형 고품격 웹사이트(쇼핑몰, 기업 소개, 의전/상례 서비스 등)를 기획부터 인터랙티브 애니메이션, 실물 미디어 에셋 영구화, 사용자 입력 금액 완전 복원 및 프리렌더링, 관리자 권한 기반 UI 격리 및 미디어 통합 관리, **고객 문의 실시간 감지 및 원클릭 전화/문자(SMS) 답장 파이프라인**, Supabase 클라우드 데이터베이스 연동, 그리고 **관리자가 수정한 내용이 배포 사이트(GitHub Pages)에 즉시 적용되는 실시간 자동 배포 파이프라인**까지 일관된 최고 품질로 구축하기 위한 체계적인 표준 실행 가이드입니다.

## 2. 고객 상담 문의 라이프사이클 관리 (알림 감지 ➔ 실시간 답장 ➔ 완료 체크)

### [질문 1 해결] 관리자는 고객 문의가 들어온 것을 어떻게 확인하는가?
1. **상단 네비게이션 실시간 알림 뱃지 (상시 점등)**:
   - 미처리 문의(`status === '대기'`)가 1건이라도 있으면, 헤더의 관리자 버튼 옆에 빨간색 펄스 뱃지(`<span id="headerInquiryBadge" class="bg-red-500 ... animate-pulse">신규 N</span>`)가 자동으로 켜짐.
   - 관리자가 사이트에 접속하기만 해도 신규 문의 존재 여부를 즉시 시각적으로 인지할 수 있음.
2. **브라우저 데스크톱 팝업 알림 (Notification API)**:
   - 관리자 콘솔에서 `[🔔 브라우저 알림 권한 켜기]`를 클릭해두면, 사이트를 다른 탭에 띄워두거나 백그라운드에 두어도 신규 문의 접수 시 윈도우 우측 하단에 알림 팝업(`🔔 [백재상례복] 홍길동 님의 새 상담 문의가 접수되었습니다`)이 즉시 뜸.
3. **고객 접수 시 직통 긴급 연결 안내**:
   - 고객이 문의 접수 시 즉시 담당자 직통 전화(`010-3112-6730`)와 접수 확인 팝업을 출력하여 즉시 통화 연결을 유도.

### [질문 2 해결] 관리자는 고객 문의에 어떤 방식으로 답장하는가?
상례복 및 장례 의전 서비스는 긴급성이 매우 높으므로, 이메일이 아닌 **원클릭 전화 및 문자(SMS) 즉시 답장 파이프라인**을 제공:
1. **📞 원클릭 전화 통화 (`tel:`)**:
   - 고객 카드의 `[📞 전화 통화]` 버튼을 누르면 스마트폰 다이얼러나 PC의 전화 연결 앱이 실행되어 고객 번호로 즉시 통화 연결.
2. **💬 원클릭 문자(SMS) 즉시 답장 (`sms:`)**:
   - `[💬 문자(SMS) 답장]` 버튼을 누르면 고객 번호 및 사전 작성된 정중한 상례복 상담 안내 인사말이 자동으로 채워진 문자 발송 창이 바로 호출됨:
     ```
     [백재상례복] 안녕하세요 홍길동님, 홈페이지에 남겨주신 상례복 상담 문의에 대해 안내드립니다.
     ```
3. **📝 관리자 상담 메모 & 답변 기록 기능**:
   - 문의 건별로 하단에 `📝 상담 메모` 입력란 제공.
   - 통화 결과, 유가족 체형 정보, 장례식장 주소, 배송 예정 시간 등을 메모하고 `[메모 저장]`을 누르면 영구 기록 보존.

### [질문 3 해결] 완료 여부 체크 및 상태 관리는 어떻게 하는가?
1. **원클릭 상태 토글 (`대기` <-> `상담 및 처리완료`)**:
   - 각 문의 카드 상단의 `[● 상담 대기중 (클릭시 완료)]` 버튼을 클릭하면 즉시 `[✓ 상담 및 처리완료]` 그린 뱃지로 상태가 전환됨.
2. **상태별 필터링 기능**:
   - 상단 필터 버튼: `[전체]` / `[미처리 대기]` / `[완료]`를 통해 미처리된 긴급 문의만 모아볼 수 있음.
3. **휴지통 삭제 기능**:
   - 테스트용 문의나 불필요한 내역은 `[🗑️ 삭제]` 버튼을 통해 깔끔하게 정리 가능.
4. **로컬 스토리지 + Supabase 동시 영구 저장**:
   - Supabase 클라우드 DB와 브라우저 로컬 스토리지(`baekjae_inquiries`)에 양방향 동시 저장되어 새로고침 후에도 상태가 영구 보존됨.

## 3. 대표 이미지 업로드 및 배포 사이트 실시간 반영 워크플로우

### [원인 분석] 업로드한 이미지가 배포 사이트에 왜 안 보였는가?
- 브라우저에서 이미지 파일을 업로드하면 브라우저 내부 캐시(`baekjae_home_hero_image`)에만 저장되고, Git 저장소의 실제 파일(`home_model.jpg`)이나 Supabase(RLS 차단 상태)에는 반영되지 않아 다른 기기/외부 손님에게는 옛날 이미지가 보이게 됨.

### [해결 워크플로우] 정식 파일 번들링 & 배포 자동화
1. **Chrome LevelDB 저장소 역추적**:
   - `User Data/.../Local Storage/leveldb`에서 사용자가 실제 업로드한 Base64 이미지 데이터를 디코딩 추출.
2. **프로젝트 정식 에셋(`home_model.jpg`)으로 파일 교체**:
   - 추출된 고화질 이미지를 `home_model.jpg`로 덮어쓰기 저장.
3. **GitHub Pages 자동 푸시**:
   - `home_model.jpg`를 Git에 커밋 및 푸시하여 GitHub Pages 배포 사이트에서도 모든 접속자에게 새 이미지가 즉각 표시되도록 확정.
4. **바탕화면 원클릭 배포 파일 제공**:
   - 관리자가 PC에서 새로운 이미지를 설정한 뒤에는 바탕화면의 `배포하기_클릭.bat`을 더블 클릭하면 30초 내에 GitHub Pages 소스 코드 전체가 영구 배포됨.
